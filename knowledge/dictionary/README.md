# מרכז הידע — מילון מונחים כלכליים

מודול ראשון במרכז הידע של מצפן כלכלי: מאגר מונחים כלכליים עם חיפוש חכם
ועמוד SEO ייעודי לכל מונח.

## מבנה התיקייה

```
knowledge/
├── index.html                       ← עמוד "מרכז הידע" (רשימת מודולים; כרגע רק המילון)
└── dictionary/
    ├── terms.json                   ← כל התוכן. זה הקובץ היחיד שעורכים כדי להוסיף/לשנות מונחים.
    ├── index.html                    ← עמוד המילון הראשי (חיפוש + קטגוריות + רשימת מונחים)
    ├── search.js                      ← מנוע החיפוש (שם/כינוי/אנגלית/מילות מפתח/שגיאות כתיב)
    ├── style.css                       ← כל העיצוב (משותף לכל דפי המילון)
    ├── term-template.html          ← תבנית לעמוד מונח בודד (לא עורכים ידנית — נוצר ממנה)
    ├── generate.js                    ← סקריפט שיוצר עמוד HTML נפרד לכל מונח מתוך הטמפלט
    ├── test-search.js                 ← בדיקת רגרסיה לחיפוש + תקינות מבנית של terms.json
    ├── <slug>/index.html              ← *נוצר אוטומטית* ע"י generate.js. אל תערוך ידנית.
    └── sitemap-fragment.xml         ← *נוצר אוטומטית*. רשימת ה-URL-ים של כל המונחים (לשילוב ב-/sitemap.xml).
```

**עיקרון מרכזי:** תוכן (`terms.json`) מופרד לגמרי מקוד. כשרוצים להוסיף
מונחים חדשים — עורכים רק את `terms.json`, לא נוגעים ב-HTML/CSS/JS.

ווידג'ט הנגישות (`/static/a11y-widget.css` + `/static/a11y-widget.js`)
משותף לכל האתר — כולל דפי המילון — ולא חלק מהתיקייה הזו.

## איך מוסיפים מונח חדש

1. פותחים את `terms.json`.
2. מוסיפים אובייקט חדש למערך `"terms"`, לפי אותו מבנה של המונחים הקיימים:

```json
{
  "slug": "kebab-case-english",
  "name": "השם בעברית",
  "name_en": "English Name",
  "category": "אחד המפתחות מתוך \"categories\" למעלה",
  "aliases": ["כינוי א", "כינוי ב"],
  "keywords": ["מילות חיפוש נוספות", "כולל אנגלית/ראשי תיבות"],
  "short_explanation": "משפט אחד קולע.",
  "simple_explanation": "הסבר מורחב, בשפה פשוטה.",
  "why_it_matters": "למה זה חשוב לקורא הספציפי.",
  "example": "דוגמה מספרית או מוחשית.",
  "common_mistake": "טעות נפוצה שאנשים עושים סביב המושג הזה.",
  "what_to_check": "צ'ק-ליסט קצר של מה לבדוק בפועל.",
  "related_terms": ["slug-של-מונח-קשור"],
  "sources": [{ "label": "שם המקור", "url": "https://..." }],
  "last_updated": "YYYY-MM-DD",
  "volatile": false
}
```

השדה `volatile` הוא אופציונלי — מסמנים `true` על מונחים שמכילים אחוזים
או סכומים שמתעדכנים מעת לעת (כמו תקרות מימון, ריבית פריים, תקרות מס),
כדי שאפשר יהיה בעתיד להפיק דוח "מונחים לבדיקה תקופתית".

3. מריצים בטרמינל, מתוך תיקיית `knowledge/dictionary`:

   ```
   node generate.js
   node test-search.js
   ```

   `generate.js` יוצר/מעדכן את `<slug>/index.html` לכל מונח, ומרענן את
   `sitemap-fragment.xml`. `test-search.js` מוודא שהחיפוש עדיין עובד נכון
   ושאין slugs כפולים או `related_terms` שבורים — **מריצים לפני כל commit**.

4. אם `sitemap-fragment.xml` השתנה (מונח חדש נוסף) — מוסיפים את הכתובת
   החדשה ידנית גם ל-`/sitemap.xml` הראשי של האתר.

5. מעלים (deploy) כרגיל.

## הרצה מקומית לבדיקה

`index.html` טוען את `terms.json` באמצעות `fetch()`, ורוב הדפדפנים חוסמים
`fetch` לקובץ מקומי (`file://`). כדי לראות תצוגה מקדימה במחשב, צריך שרת
מקומי פשוט מתוך שורש האתר (לא מתוך `knowledge/dictionary` — כל הנתיבים
בקבצים הם מוחלטים, למשל `/static/...`, `/knowledge/dictionary/...`),
למשל:

```
python3 -m http.server 8080
```

ואז לפתוח `http://localhost:8080/knowledge/dictionary/`. באתר עצמו
(מוגש דרך Netlify) זה עובד ישירות בלי הגדרה נוספת.

## הרעיון מאחורי החיפוש (`search.js`)

החיפוש **לא** מבוסס על `includes()` פשוט. סדר העדיפויות:

1. התאמה מדויקת בשם / שם באנגלית / כינוי
2. התחלה זהה (למשל "פרי" בתחילת "פריים")
3. הכלה בשם/כינוי/מילת מפתח
4. הכלה בהסבר הקצר
5. התאמה מקורבת (סובלנית לשגיאות כתיב, למשל "נסדק" ⇠ "נאסד״ק")

שלב 5 מוגבל בכוונה (רק מילים באורך 4+, עם הפרש אורך קטן מהשאילתה)
כדי למנוע התאמות שווא. אם מוסיפים הרבה מונחים ונתקלים בהתאמות שגויות
או חסרות, `search.js` הוא המקום לכייל את הספים — **חובה להריץ
`node test-search.js` אחרי כל שינוי כזה.**

## מה עוד לא בנוי (מכוון, ל-V1)

- מסך ניהול ויזואלי להוספת מונחים (כרגע עורכים `terms.json` ישירות).
- קישורי "מחשבון רלוונטי" מדף מונח למחשבונים הקיימים באתר — לא נוסף
  עדיין, כדי לא לקשר למחשבון לא-רלוונטי בטעות. אפשר להוסיף שדה
  `related_calculator` ל-`terms.json` בהמשך, אחרי בדיקה ידנית של כל
  מחשבון מול כל מונח.
- שכבות נוספות במרכז הידע ("איך זה עובד" / "זכויות כלכליות" / "מספרים
  שצריך להכיר") — המבנה תוכנן כך שקל להוסיף אותן בהמשך כתיקיות אחיות
  תחת `/knowledge/`.
- 100–150 המונחים המלאים — כרגע יש 11 מונחים לדוגמה, אחד מכל קטגוריה
  עיקרית. **כל תוכן פיננסי חדש צריך אישור של יוסי לפני deploy.**
