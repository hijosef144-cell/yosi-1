# כרזת השקה — מצפן כלכלי (תיעוד תחזוקה)

רכיב משותף אחד לכל העמודים הציבוריים: `static/launch-banner.js` + `static/launch-banner.css`.
כל עמוד טוען אותו בתגית אחת: `<script src="/static/launch-banner.js" defer></script>` (בסוף ה־`<head>`).

## הוספה, בדיקה והסרה
```bash
node scripts/apply-launch-banner.js            # מוסיף את התגית לכל עמוד ציבורי שחסר בו (בטוח להרצה חוזרת)
node scripts/apply-launch-banner.js --check    # בודק: כל עמוד ציבורי עם תגית, ואף עמוד פנימי בלי
node scripts/apply-launch-banner.js --remove   # מסיר את התגית מכל העמודים (כיבוי מלא של הכרזה)
```
אחרי מיזוג ענף שהוסיף עמודים (או שינה `<head>`) מריצים שוב את הסקריפט. עמודי ניהול (`admin/`), כספכם (`kaspchem/`),
בדיקות, תיעוד וכלי עזר לא מקבלים את התגית, והרכיב עצמו מסרב לרוץ בנתיבים `/admin`, `/kaspchem`, `/portal`, `/api`.
דף שצריך לוותר על הכרזה: מוסיפים `data-lb-off` לתגית `<html>`.

## התנהגות
- כניסה ראשונה בביקור: כ־3 שניות אחרי הטעינה, אנימציית פתיחה אחת. **ברירת המחדל היא כרזה פתוחה וגדולה**: בדסקטופ המגילה נפתחת במלואה
  (מגילה מעוגנת כשיש מקום בצד, ובמסכים עם מעט מקום היא נפתחת כחלונית גדולה של 312px שאפשר למזער), ובנייד נפתחת אוטומטית חלונית תחתונה של בערך
  חצי מסך (עד 58% מהגובה, בלי הכהיה ובלי חסימת הדף). הפתיחה האוטומטית מתבצעת פעם אחת בביקור: לא למי שמיזער, לא למי שכבר נרשם, ולא בעמודים הבאים
  (שם נשארת הגרסה הקטנה, כדי לא לכסות מחשבונים ושדות). מעבר לעמוד אחר לא מפעיל אנימציית פתיחה ולא מאפס מצב.
- מזעור נשמר לאורך הביקור (`sessionStorage`, מפתח `lb.s1`). סגירה נשמרת 7 ימים (`localStorage`, מפתח `lb.v1`, שדה `closedUntil`).
  נרשם בהצלחה: לא מציגים שוב טופס באותו דפדפן (`lb.v1.joined`).
- חלון הרשמה אחד: כל עוד הכרזה פעילה (`window.__lbActive`), פופ־אפ המדריך החינמי (יציאה מהאתר, `index.html`) לא נפתח.
- מצבי תצוגה (`tierFor`): נקבעים לפי הרוחב **הפנוי בצד ימין** של העמוד עצמו: המרחק בין קצה המסך לקצה הימני של התוכן שמתחת לכרזה
  (טקסט נמדד לפי הטקסט עצמו, והכותרת העליונה של האתר, שהכרזה תלויה מתחתיה, לא נחשבת). כך הכרזה לא מכסה תוכן:
  מקום ‏≥338px: מגילה גדולה (312px); ‏≥252px: מגילה בינונית (230–311px) עם אותו תוכן וטופס; ‏≥94px: מגילה קטנה (68px) שלחיצה עליה פותחת חלונית הרשמה;
  ‏≥30px: לשונית צד; אחרת (וגם כל מסך צר מ־1100px, וכל מכשיר מגע ברוחב קטן מ־1420px): פס תחתון + חלונית הרשמה.
  הפס התחתון מרים מעליו את הכפתורים הצפים ואת באנר העוגיות. הבחירה נבדקת שוב 2.5 שניות אחרי הטעינה ובכל שינוי גודל חלון.
- הרשמה: `POST https://matzpen-crm.netlify.app/api/email/initiative-waitlist` (ראו הדוח של ה־CRM). הצלחה מוצגת רק על תשובת 201 עם `ok:true`.
  בכל שגיאה האימייל נשאר בשדה. אין ניסיון חוזר אוטומטי.

## כלי בדיקה (לא פעילים בדומיין הייצור)
`?lbDemo=ok|err|verify` מדמה תשובת שרת באתרי תצוגה מקדימה; `?lbApi=http://127.0.0.1:PORT` (רק ב־localhost);
`?launch=reset` מאפס את המצב בדפדפן (בכל דומיין). נוסח ההסכמה וגרסתו (`2026-11-v1`) חייבים להיות זהים לקבוע שבשרת: שינוי נוסח = גרסה חדשה בשני הצדדים.

## בדיקות
```bash
node tests/launch-banner/server.js &             # שרת סטטי מקומי (פורט 4190)
npx playwright test -c tests/launch-banner/playwright.config.js                       # פריסה, מצב, הרשמה מול CRM מדומה, נגישות, ביצועים, כל העמודים
npx playwright test -c tests/launch-banner/playwright.real-crm.config.js              # הרשמה מול אפליקציית ה־CRM האמיתית על מסד זמני בזיכרון
```
בדיקות ה־CRM האמיתי דורשות את ענף ה־CRM (`initiative-waitlist`) בתיקייה אחות (`CRM_WORKTREE`). כל הבדיקות מקומיות: אין מסד אמיתי ואין שליחת מייל.
